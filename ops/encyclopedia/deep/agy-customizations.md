## Summary
A built-in SIR operating system customization skill that manages session checkpoints, progress tracking, and cross-tool synchronization for the SIR agent workflow. It reads and writes the `PROGRESS-slice-N.md` files, maintains the `SKILLS_INDEX.md`, and coordinates the `propagate-deep.mjs` and `build-encyclopedia.mjs` scripts to keep skill digests consistent across all tool folders. The skill ensures that when one worker finishes a slice, the next worker can resume exactly where the previous one left off, with minimal context loss.

## When to use / when NOT
Use when starting a new SIR round, migrating between agents, or transferring work between sessions. It is the default mechanism for maintaining state across model turns. Do NOT skip this skill when working in a multi-model environment — without it, each new model must re-read all context from scratch, leading to redundant work and potential inconsistencies. Do NOT use for ad-hoc one-off tasks that don't involve skill encyclopedia management.

## Inputs, outputs, tools
- Inputs: session directory path, slice number, progress file path, tool directory list.
- Outputs: updated PROGRESS-slice-N.md, refreshed SKILLS_INDEX.md, propagated deep digests to all tool folders, committed checkpoint.
- Tools: filesystem read/write, git commit/push, node.js scripts (build-encyclopedia.mjs, propagate-deep.mjs, gen-index.mjs). MCP: antigravity-builtin connector.

## 5 most important rules
1. **Always update PROGRESS-slice-N.md before stopping** — record the done count and next skill so the next worker can resume exactly.
2. **Commit and push all changes to main** after each slice is complete — the progress file and deep digests must be visible to the next worker.
3. **Run `node gen-index.mjs`** after updating deep digests to regenerate the Skills Index with current category and tool mappings.
4. **Do not modify the SKILLS_INDEX.md manually** — it is generated by the script; manual changes will be overwritten on the next run.
5. **Protect legacy/ and AI_Models_Hub/ from pruning** — the checkpoint system knows to skip these directories, but manual git resets can cause data loss.

## Risks / owner notes
Failing to update the progress file is the most common failure mode — the next worker will start from the wrong skill or redo already-completed work. The owner should verify that the progress file is committed and pushed before ending a session. Cross-tool digest propagation (gemini-plugin with <plugin>--<skill> naming) can create naming collisions if skill names are not unique.
