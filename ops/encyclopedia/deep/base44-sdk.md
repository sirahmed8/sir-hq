## Summary
"Base44 Coder" — the guide for building features in an EXISTING Base44 project with the `@base44/sdk` JavaScript/TypeScript SDK. It covers the full module surface: `entities` (CRUD + filter/sort/subscribe/import), `auth` (login/register/me/updateMe), `agents` (AI conversations), `functions.invoke` (backend functions), `actors` (stateful realtime WebSocket rooms), `integrations.Core` (InvokeLLM, SendEmail, UploadFile, GenerateImage/Video), `aiGateway` (code agents, images, video, speech, Jev decisions), `analytics`, `appLogs`, `users`, and backend-only `asServiceRole` (entities, functions, connectors, sso). Its signature contribution is a large WRONG-vs-CORRECT table of hallucinated API names agents tend to invent from Firebase/Supabase patterns.

## When to use / when NOT
Use when implementing features in a project where `base44/config.jsonc` already exists and `@base44/sdk` imports are present — CRUD, auth flows, functions, realtime actors, AI/LLM calls, integrations. Do NOT use it to initialize a new project or run CLI commands (base44-cli), and do NOT use it before checking the project state — in an empty directory it must defer to base44-cli.

## Inputs, outputs, tools
- Inputs: an initialized Base44 project, the feature request, entity/function/actor names (types generated by `npx base44 types generate` augment `EntityTypeRegistry`/`FunctionNameRegistry`/`ActorNameRegistry`/`AgentNameRegistry`).
- Outputs: TypeScript/JavaScript code using the correct SDK modules and method names.
- Tools: `@base44/sdk` (`createClient({ appId })` — `appId`, never `clientId`/`id`; `createClientFromRequest(req)` in backend functions), the 14 reference files, base44-cli for type generation. MCP: none.

## 5 most important rules
1. **Verify every method name against QUICK_REFERENCE.md before writing code** — the skill exists because agents hallucinate Firebase-style names; e.g. `loginViaEmailPassword` not `signInWithEmailAndPassword`, `functions.invoke` not `functions.call`, `entities.Task.filter/get/create/delete/subscribe` not find/findOne/insert/remove/onChange.
2. **`functions.invoke()` returns the raw axios response** — the function's JSON is on `.data`, and it throws on non-2xx (error body at `err.response.data`).
3. **Actors vs entities subscribe differ**: `actors.X(id).connect()` returns a connection whose `subscribe(cb)` yields `{ unsubscribe() }`; `entities.X.subscribe(cb)` returns the unsubscribe function itself.
4. **Actor messages are attacker-controlled** — always validate `msg?.type`/payload shape in `handleMessage`, broadcast with `this.broadcast`, use `conn.identity.userId` for attribution and `this.client.asServiceRole` for canonical persistence.
5. **`asServiceRole`, `aiGateway`, and `asServiceRole.connectors/sso` are backend-only** — never call them from frontend code; actors receive no app secrets.

## Risks / owner notes
Wrong SDK names are the #1 failure mode — the anti-hallucination tables are the skill's core value; skip them and you ship broken code. `asServiceRole` bypasses permissions — keep it in backend functions only. AI gateway calls (InvokeLLM, image/video/speech) consume the app's Base44 quota.
