# dart-use-ffigen (Flutter plugin)

## Summary
Guide for generating Dart FFI bindings with `package:ffigen` instead of hand-writing `dart:ffi`: configure `FfiGenerator` in `tool/ffigen.dart` (Headers entryPoints/include/compilerOptions, Functions include/isLeaf/recordUse, Structs/Enums/etc., required Output with license preamble), keep third-party headers in `third_party/`, emit bindings to `lib/src/third_party/*.g.dart` with a "do not edit" preamble matching the native license, and — for runtime/native-assets use — enable `recordUse` + a `record_use_mapping` `.g.dart` file for linker tree-shaking.

## When to use / when NOT
Use when writing new FFI bindings or extending C/Obj-C/Swift integrations where headers exist or are build-generated. Hand-written `DynamicLibrary.lookup`/external functions are explicitly banned when headers are available.

## Inputs, outputs, tools
- Inputs: native headers (`.h`), pubspec deps (`ffigen` dev, `code_assets`/`hooks`/`native_toolchain_c`/`record_use` for native assets).
- Outputs: generated `*.g.dart` bindings + optional record-use mapping.
- Tools: `package:ffigen` `FfiGenerator`, libclang under the hood; run generator then `dart analyze`.

## 5 most important rules
1. Never hand-write FFI bindings when headers exist — always FfiGenerator.
2. Generator lives at `tool/ffigen.dart`; third-party headers under `third_party/` (or src/); generated output under `lib/src/third_party/` with `.g.dart`.
3. Use targeted inclusion filters (Functions.includeSet / include closures) — never bind an entire library wholesale.
4. Preamble must carry the target package license + native copyright + "Generated by package:ffigen" warning.
5. For native-assets/tree-shaking: `recordUse: (_) => true` and `recordUseMapping` pointing to a `.g.dart` under `lib/src/third_party/`; run the generator and verify diffs BEFORE finishing.

## Risks / things needing the owner
FFI binds real native code — wrong signatures crash at runtime; regenerate bindings when headers change and commit the diff. Third-party license headers must be preserved.
