## Defects found and fixed (all logged in `.sir/DEFECTS_20261114-1231.md`)

The automated sweep itself was clean (overflows 0, touch 0, motion clean,
print/zoom/wide clean, consoleErrors 0), so the real findings came from the
code-level hunt. 9 defect clusters fixed, covering 15+ visible behavior
changes (>10 visible improvements required by the brief):

1. **D1 — Theme state divergence across four switch paths.** The `t`
   keyboard shortcut, palette "Toggle theme", context-menu toggle and the
   settings segmented control each updated a different subset of UI,
   leaving dropdown `.active`/checkmarks and segmented `aria-checked` stale
   and toasts English-only. Fix: single `app.setTheme(val)` in
   `src/public/js/theme.js` persists, resolves `system`, syncs both
   controls via `syncThemeControls()`, localized toast via `theme.*` i18n
   keys; all four call sites delegate; re-selecting current theme is a
   silent no-op.
2. **D2 — `showToast` ignored its `kind` argument; FX toasts English-only.**
   `api.js` passed `'error'`/`'success'` to a one-argument `showToast`,
   silently dropped, and all 8 FX strings were hardcoded English in the AR
   UI. Fix: `showToast(message, kind)` maps kinds to `toast-error` /
   `toast-success` classes (new accent-bar styles in `app.css`, no layout
   shift); FX toasts localized EN/AR.
3. **D3 — Clipboard writes crashed on non-secure (http://LAN) origins.**
   `copyCashProposal`, `copyPitchText`, `copyProfileProposal` called
   `navigator.clipboard.writeText` directly; on the LAN daemon origin
   `navigator.clipboard` is undefined → TypeError, zero feedback, dead
   button. Fix: shared `app.copyPlainText(text)` in `dialogs.js`
   (Clipboard API then `execCommand('copy')` fallback, resolves boolean);
   all four copy sites routed through it with success/error toast kinds.
4. **D4 — Context-menu "Refresh View" silently skipped contacts.**
   `refreshCurrentView()` loaders map lacked `contacts` — toasted
   "Refreshing..." but never reloaded. Added
   `contacts: () => this.loadContacts()`; all 8 views covered.
5. **D5 — Overdue follow-up rendered as "-3 days remaining".**
   `showApplicationDetail` printed negative `daysUntilFollowUp` with a
   neutral badge. Fix: negative values render `N days overdue` /
   `N أيام تأخير` with new `.badge-danger` token-driven style.
6. **D6 — Dead `href="#"` links on missing intake/apply URLs.**
   `sanitizeUrl()` returns `'#'` for non-http(s) input and five render
   sites eagerly emitted `<a href="#">` (job card Apply, job-detail
   portal, application-detail portal, proposal Direct Portal, Open
   Intake Portal, verifiedLinks badges). Clicking scrolled to top / did
   nothing. Fix: every site checks `u !== '#'` and renders a disabled
   control or muted "No intake link" label.
7. **D7 — `quickApply` opened unvalidated URLs and lied about the
   outcome.** `window.open(url)` ran on the raw `submissionUrl` and the
   toast always claimed the portal opened. Fix: only http(s) URLs opened;
   toast distinguishes copied+opened vs copied-only with the right kind.
8. **D8 — Profile view crashed without `exchangeBenchmark`.**
   `renderProfile` dereferenced `fx.targetEgp.toLocaleString()` etc.
   unguarded; a payload with `candidate` but no benchmark block would
   throw mid-render leaving a blank view. Fix: `exchangeBenchmark || {}`
   plus per-field guards.
9. **D9 — TLS diagnostic printed "(undefined)".**
   `loadTlsDiagnostic` interpolated `data.tailnetHost` unguarded; falls
   back to `'local'`.

Also fixed during the round: an em-dash I introduced in the profile FX
