## Defects fixed (ledger: `.sir/DEFECTS_20261113-2241.md`)

- **D1 - Touch targets below 44px** on ~14 controls (`btn-control`, `btn-sm`, `btn-card`,
  `banner-details-btn`, `banner-dismiss`, `header-chip`, `skip-link`, drawer buttons, `.switch`,
  `.deadline-chip`, `.palette-item`, `.btn-icon`/`.modal-close-btn`, `.btn-link`,
  `btn-settings`/`btn-mobile-search` widths). All moved to `var(--touch-target-min)` (44px).
- **D2 - Harness false positive**: sr-only `tabindex="-1"` buttons excluded from touch/motion checks.
- **D3 - ROOT CAUSE: invalid CSS transition shorthand.** `--trans-fast`/`--trans-norm` tokens
  already bundle duration+easing, so `padding var(--trans-norm) var(--ease-spring)` (and two
  siblings on `.bottom-nav-item`, `.switch-thumb`) is an invalid shorthand - the browser silently
  discards the whole `transition` declaration. That is why nav tabs, bottom-nav items and the
  switch thumb computed `transition: all 0s`. Fixed by removing the redundant easing vars; added
  missing transitions to `.btn-icon`, `.palette-item`, `.btn-drawer-collapse`, `.btn-link`.
  Regression guard in the new test forbids the `var(--trans-*) var(--ease-*)` pattern.
- **D3b - Switch thumb jumped ~12px when toggled**: checked state set
  `transform: translateX(22px)`, discarding the base `translateY(-50%)` centering. Now
  `translateY(-50%) translateX(±22px)` (RTL aware).
- **D4 - Bottom nav rendered at 768px tablet breakpoint**: `.mobile-bottom-nav` now defaults to
  `display:none` and only renders inside `max-width: 767px`.
- **D5/D8 - Offline status dot stayed green, twice over:**
  - App: `syncConnStatus()` reads `navigator.onLine` and toggles `.security-dot.is-offline`
    (warning colour + 1.2s pulse) - moved from inline styles to a CSS class, which also brought
    the JS bundle back under the 185KB budget (was 185.1KB, test-a11y-ui was failing on main).
  - **Stale immutable assets (the deep find):** `app.css?v=3.3.0` / `main.js?v=3.3.0` are served
    `Cache-Control: immutable` for 1 year. CSS changed all day without a `?v=` bump, so returning
    visitors - and the audit's own browser session - ran new JS against old CSS (proved in
    cycle 3: `is-offline` class toggled but no CSS rule existed -> dot stayed green under real
    offline emulation). Fixed: `?v=` bumped to 3.3.1 on all three index.html refs,
    `sw.js` CACHE_NAME v14 -> v15, and the audit harness now calls
    `Network.setCacheDisabled` so sweeps always test live assets.
    **Process rule recorded in checkpoint + ledger: any `?v=` asset change requires bumping the
    version token and the SW cache name.**
- **D6 - Checkbox touch-target false positive (harness correction):** `#pipeline-filter-proof`
  is a 24px glyph inside `<label class="filter-check">` (already >=44px) - the label IS the
  pointer target per WCAG 2.5.8. Harness now measures `closest('label')` for checkbox/radio.
- **D7 - `.btn-link` real defect + hidden-subtree false positives:** `#settings-open-target-btn`
  had `min-height: 36px` and no transition - fixed. The 6 `.bottom-nav-item` motion hits were
  elements inside `display:none` `.mobile-bottom-nav` at 1280px whose own computed display is
  still `flex`; motion check now skips `getClientRects().length === 0`.
