## Cycle 1: Code inspection + local verification

### Defects found and fixed (3 defects)

**D15 - Contact form email input had hardcoded dir="ltr"**
- Root cause: `#contact-email` input had `dir="ltr"` hardcoded, which would cause bidirectional text issues when user enters Arabic text. Following the pattern used by all other form inputs which use `dir="auto"`.
- Fix: `src/public/index.html` - changed `dir="ltr"` to `dir="auto"` on `#contact-email` input.
- Evidence: dir attribute now matches the `dir="auto"` pattern used by contact-name, contact-role, contact-company, contact-notes inputs.

**D16 - Contact form last-contacted date input had hardcoded dir="ltr"**
- Root cause: `#contact-lastContacted` input had `dir="ltr"` hardcoded, which would cause bidirectional text issues when user enters Arabic text. Following the pattern used by all other form inputs which use `dir="auto"`.
- Fix: `src/public/index.html` - changed `dir="ltr"` to `dir="auto"` on `#contact-lastContacted` input.
- Evidence: dir attribute now matches the `dir="auto"` pattern used by other contact form inputs.

**D17 - FX manual rate input aria-label was hardcoded English**
- Root cause: `#fx-manual-input` had `aria-label="Manual Exchange Rate"` hardcoded in English, without going through the i18n system. This means the label would not be localized when the user switches to Arabic mode.
- Fix: 
  - `src/public/i18n/en.json` - added `"target.rateAriaLabel": "Manual Exchange Rate"` key
  - `src/public/i18n/ar.json` - added `"target.rateAriaLabel": "سعر الصرف اليدوي"` key
  - `src/public/index.html` - changed `aria-label="Manual Exchange Rate"` to `data-i18n-aria-label="target.rateAriaLabel"` so the i18n system can translate it.
- Evidence: aria-label will now be translated via the i18n system when language changes.
