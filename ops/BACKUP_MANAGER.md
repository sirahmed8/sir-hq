# Backup manager through Telegram (owner order 2026-11-12, r64 rework)
- Switch on: send the bot `/takeover` (or the menu button). Switch off: `/handback`. State file: ops/backup-manager.json (written atomically by the listener before anything async).
- While on, messages from Ahmed are collected into ONE burst job: an 8 second debounce after the last message groups text + voice + photos (media_group_id albums included) so the manager sees everything together. The queue survives restarts in ops/backup-manager/queue.json; a running job is tracked in ops/backup-manager/job.json and its stage in job-state.json.
- Ack is instant (reaction + typing). scripts/backup_manager.py then downloads media, transcribes every voice note and describes every photo IN PARALLEL, builds one ordered prompt (ops/BACKUP_MANAGER_PROMPT.md + recent chat + the whole burst), and races TWO free agents from the pool (150 s per attempt, first valid reply file wins). Fastest entries are remembered in ops/backup-manager/latency.json. Chat memory: ops/backup-manager-chat.jsonl. Logs: ops/agy-runs/backup-manager.log.
- Commands while on: /status shows queue depth, current job stage and fastest models; /handback and /takeover always work (commands are matched before the backup-mode branch and the bot mention is stripped).
- Order of managers: Claude, then Antigravity (when it is available again), then the free tools.
- The backup manager uses the computer and Chrome through the SIR Autonomy MCP server (registered in opencode and kilo) and the skills library.
