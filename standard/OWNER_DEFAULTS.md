# Defaults every project and agent applies from day one (Ahmed, 2026-11-09 to 2026-11-11). Read with ops/WORKER_PREAMBLE.md; update when he gives a new standing rule, so no project needs the chat repeated.
1. Quality: premium UI, spring animations, one shared component per pattern (tab bars and segmented controls draggable by finger), five states on every view, nothing clipped at 320 to 1920 px, Arabic RTL and English, light and dark; browser tests for layout invariants; the agent finds defects before the owner does (self-audit loops until two clean cycles).
2. Names and hosting: own Firebase project and own repo named after the product; every public site on Firebase Hosting AND Vercel, same build, same environment variables set on both (AI keys and any .env values must exist in the Vercel project settings too); both addresses curl-checked.
3. Truth: nothing marked working until seen working; CI green is required; no invented numbers; profiles and CV say Vibe Coder only; no fixed income figure.
4. Privacy: AHome and Habiba data never leave AHome; never read or write the TickTick note Accounts; secrets only in ignored files and env vars; _local/ is the place for private exports.
5. Messages to the owner: title, at most 5 one-fact lines, one action or nothing needed; buttons for questions; Egyptian Arabic.
6. Automation: Windows background tasks, pause during games, low priority while he works, independent of any chat; test browsers headless, muted and always closed.
7. Initiative: agents suggest and advise, capture new ideas into the right plan in the same turn, adapt improvements from one project to the others (new component, new rule, new fix) and record them here.
8. College work: help him learn (summaries, practice sets, worked examples, flashcards, mock quizzes); never solve graded work for submission.
9. Jobs: apply automatically to vetted truthful matches (cap 10 a day), report every application and every first answer.
10. Integrations: link every useful account (Google Workspace, TickTick, Telegram, WhatsApp read-only) through the app's own OAuth, with five states and a retry.
11. AI calls in every project follow plans/AI_FALLBACK_CHAIN.md: Gemini flash-lite-latest, then flash, then any Gemini, then OpenRouter free models, then other free providers, then local; one key per project created on that project's own Firebase/GCP project and its own OpenRouter key.
12. Times: scheduled jobs use round times (:00 and :30), never odd minutes, except prayer-based duties.
13. Desktop face: every product with a Windows app follows plans/WINDOWS_APP_STANDARD.md (real installer, Google sign-in on Firebase, self-updating to the latest build, a Download page on the site, a private repo with production-only release builds, a per-project Product Kit folder, an entry in Projects-Hub.html).
14. Native-app feel on every public site (owner, 2026-11-11): disable the browser's default text-selection and right-click context menu; replace the context menu with the app's own (relevant in-app actions, plus a generic refresh); never block real input fields from normal select/copy/paste. No visible browser chrome affordances that make it feel like "a website" instead of "a program".
15. Bidi text everywhere (owner, 2026-11-11): every text input must detect Arabic vs Latin per character as the user types and set direction/caret side live (Arabic starts/types from the right, Latin from the left), like WhatsApp/Telegram's own composer. Every place that renders mixed Arabic+English content must isolate each run's direction (`<bdi>` or `unicode-bidi: isolate`) so mixed text never scrambles or reorders. Never show literal direction markers or parentheses like "(RTL)"/"(LTR)" to the user.
16. Personalization and locale (owner, 2026-11-11): every public product must work well for ANY visitor, not only the owner - personalize per signed-in user (not hard-coded to him), and auto-detect currency/region from the visitor's locale/IP, never a manual currency picker as the only way to set it (a manual override on top of the auto-detected default is fine).
17. Bots (owner, 2026-11-11): follow plans/BOT_ARCHITECTURE.md - one bot per product, every user links their own account to it, never a bot per user.
18. Idea sourcing (owner, 2026-11-11): before writing or rewriting a project's MASTER_PLAN/ARCHITECTURE, check the project's own `legacy/` folder AND the owner's TickTick notes (`30-Day Projects Sprint`, and the project-ideas notes in `My notes`, column "Me", never the "habobty" column) for older ideas and plans he wrote himself; port real ideas forward explicitly (cite where an idea came from) rather than silently rebuilding thinner than what he already asked for.

## Adopted from SIR Jobs
- Browser audit probe that composites translucent ancestor backgrounds AND every gradient stop before computing WCAG contrast, and treats a wrapping <label>/pseudo-element hit area as the real touch target (.sir audit scripts audit-0841*.mjs).
- Escaping discipline for vanilla-JS views: escHtml() for every interpolated text/attribute, escapeJs() only inside inline handler args, and a safeHref() allowing only http(s) for every external link (dialogs.js safeHref).
19. Desktop folder kit (owner, 2026-11-12): every product has a real folder on the Desktop under SIR Projects with its own folder.ico (the file named folder.ico in the project root, never icon.ico and never assets/brand), the project shortcuts that exist (web links for both hosts, Start dev and Stop dev, Windows app, Android APK, iOS install guide, Open project folder) and a Versions.txt (1.0.0, plain status). When a project is rebuilt from zero, its milestone M0 recreates these from scratch for the new build (the old ones belonged to the legacy version). Never an HTML page instead of the real folder.
20. Team (owner, 2026-11-12): all free tools work at the same time; tasks are spread over every tool (the pool rotates, least recently used first; output-only tasks may run in parallel in one folder with parallel_ok). Local AI is not used for coding.
21. Contacts and names (owner, 2026-11-12): contact names are Prefix + First Name only (the full name in First Name), no middle, last or company names added; titles are written one way only (Mr., Mrs., Dr., Capt, Chief, 3mo, 3m, Alshikh, Khalo, Hr.), Arabic and Franco spellings of the same name are unified; Google and Apple hold the same people.

## Adopted from SIR Control Room
- One generated file, byte-identical mirrors (SIR Control Room, 2026-11-12): a page that is published, served locally and archived must come from one build. The generator writes the page once and copies the same bytes to every place it is served from, and it writes the content hash into a small state file. A state file that claims something succeeded may only be written when it really succeeded (the publish helper once recorded a hash for a run that said "not published"). Compare such state files by value, never as whole strings.
- Browser tests must skip, not fail, when the browser is missing (SIR Control Room, 2026-11-12): the test helper finds Node.js and the Chromium build and skips with a clear reason when either is absent, so the suite stays green on a machine without them. Local browser checks walk every view at 320/390/768/1280 px in both languages and both themes.
22. Rescan rule (2026-11-12): every AI re-reads a whole project and improves its plan (research, detail, more tasks) before working on it, and again at each milestone; see ops/WORKER_PREAMBLE.md rule 20. Small ideas are separate small projects (plans/PRODUCT_DIRECTION_2026-11-12.md section 8). SIR Business has a specialised app and site per sector.
