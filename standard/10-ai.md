# 10 — AI features (AI is at the core of every product)

Ahmed's direction: AI is the most important part of every app. Every product is designed around AI that does real work for its users. It runs on free tiers by spreading requests across several providers with automatic fallback, and it stays usable when every provider is busy.

## What every product ships

- **A flagship AI feature tied to the core job**, something users would choose the product for, never a chatbot bolted on. The "AI at the core" column in `D:\Projects\_SIR\core\06-portfolio.md` proposes one per product line.
- **An in-app assistant** that answers from the product's help center and, with permission, the user's own data, and takes actions through the product's real functions. It asks the user to confirm anything with side effects.
- **AI across the experience:** natural-language search over the user's own data, summaries, translation into every project locale, voice input and read-aloud, image understanding where it helps (receipts, meals, documents, products, scenes), and smart suggestions and reminders.
- **Reach beyond the app:** expose the main actions to the system assistants (App Intents for Siri, Shortcuts and Spotlight on Apple platforms; Android's app-function and shortcut APIs for Gemini on Android; verify the current APIs). Where it helps users, offer an MCP server so AI assistants such as Claude or ChatGPT can work with the product on the user's behalf.
- **AHome:** all of the above on local models (see the exception at the end).

## Architecture: the AI gateway

- Client `@sir/ai` → **AI gateway** (a Cloudflare Worker per product, built from a shared package) → provider adapters. Provider keys live only in the gateway's secret store. Clients never call cloud providers directly, with two exceptions: on-device models, and Firebase AI Logic for features whose data is public and non-personal (protected by App Check).
- **Capabilities, not models:** features ask for a capability (`chat`, `reason`, `vision`, `transcribe`, `speak`, `translate`, `embed`, `moderate`). The gateway maps each capability to an ordered provider chain kept in configuration (Remote Config or KV), so providers can be swapped without an app release.
- **Fallback:** try the first provider in the chain. On a rate limit (HTTP 429), an exhausted quota, a timeout or an error, move to the next. A circuit breaker skips a failing provider for a few minutes. A Durable Object tracks each provider's quota and resets it on that provider's own schedule (most free tiers reset daily).
- **Privacy routing:** every feature declares the class of data it sends.
  - **Public** (help articles, product catalogs, generic text): any provider.
  - **Personal or sensitive** (health logs, religious practice, messages, photos of people, finances, anything about a user): never a free tier whose terms use the content to improve or train models (the Gemini API free tier does). It goes on-device, to a provider whose terms exclude training (verify each), or waits for a paid tier.
- **Cost guardrails:** per-user daily quotas, a global daily cap per provider, caching of repeated answers, trimmed context, streaming, and the cheapest capable model first.
- **When every provider is exhausted:** queue non-urgent jobs until the next reset, show a clear message, and keep the whole app usable without AI. Never fail silently.

## Quality

- Prompts are code: versioned in the repo, with an evaluation set per feature (golden inputs and expected properties) run against every provider in its chain on AI-related changes and nightly (not on every PR, to save free quotas), so a fallback never means a broken answer. Arabic quality is evaluated, not assumed.
- Structured output is validated with Zod; on failure, retry with the error fed back, then use a deterministic non-AI fallback for critical paths.
- Users can rate answers (thumbs up or down with an optional note). Low-rated answers feed the evaluation sets.

## Safety

Read this together with module 04's AI section.

- Treat user, web and document content as data, never as instructions (prompt injection). Agent features get least-privilege tools, and the user confirms side effects.
- Moderate user-generated input, and generated output shown in public spaces.
- Label AI-generated content. Never present AI output as human-written or as an official source.
- **Sensitive domains:**
  - Health: not medical advice; urgent symptoms point to real help.
  - Religion: AI never generates or rules on Quran, hadith or fatwas; it only retrieves cited text from verified sources.
  - Finance and legal: informational only.
- **Store rules:** say in the privacy policy and in the app which AI providers receive what data, and get the user's permission before sending personal data to a third-party AI (Apple's guidelines require this; verify the current wording).

## AHome exception

AHome uses local models only by default (for example through Ollama; with 6 GB of VRAM, roughly 7–8B-parameter models, quantized). The phones reach them over a private connection: Cloudflare Tunnel with Access, or Tailscale (module 22). Cloud AI for AHome data is used only if Ahmed explicitly opts in, and then never with a provider that trains on the data.

Development-time AI follows the external-workforce rules in `D:\Projects\_SIR\core\03-team.md`.
