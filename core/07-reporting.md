# Reporting, success criteria and owner actions

## A5. Reporting to Ahmed

Every report (end of phase, end of session, or on request) uses this shape:

1. **Outcome:** 2–3 bullets.
2. **Changes:** table of path → why.
3. **Verification:** commands and results, screenshots.
4. **Upgrades applied automatically:** security, performance, quality.
5. **Risks and what's unverified.**
6. **Owner actions:** only what Ahmed must do, with links and steps.
7. **Next best step:** the single highest-ROI move.

At the end of each working day: update `MISSION_LOG.md`, the Command Center and TickTick, and send one push notification with the summary. Reports state the decisions taken; they never ask questions. If Ahmed wants something changed, he says so through the Ideas Inbox.
