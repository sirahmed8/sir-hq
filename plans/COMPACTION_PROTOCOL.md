# Compaction protocol (owner, 2026-11-11): nothing important may be lost when a context is compacted, cleared or handed to the next manager
Applies to Claude, Antigravity, Codex, any manager, any project agent.
1. Before any step that may compact (context near full, end of a long burst of work): update ops/RUNNING_STATE.md (agents, crons, hosts, key locations, quotas) and append an HQ note to ops/HQ_CHECKPOINT.md (Now, Next step with exact command or file, Open promises, Re-read after a reset). Add new owner requests to ops/OWNER_REQUEST_LEDGER.md the same turn, even small or unimportant ones.
2. The summary a compaction writes must keep: the current step, decisions and why, files changed, failed commands with their errors, background work running (names and ids), what is verified and what is not, every promise not yet kept, the owner's latest messages in his words when they carry a decision, and the three standing files (OWNER_METHOD, OWNER_DEFAULTS, OWNER_REQUEST_LEDGER).
3. After a compaction or reset the SessionStart hook prints the checkpoint, ops/RUNNING_STATE.md, the first part of OWNER_METHOD and the open ledger lines. The manager then reads those files in full, re-creates the session crons listed in RUNNING_STATE.md, runs python scripts/ai-status.py, and continues. Never redo finished work; never drop a small request because it looked unimportant.
4. A manager that starts fresh (Antigravity, a free model) follows the same order: START_HERE.md, plans/AI_TOOLS_CONTROL.md, ops/RUNNING_STATE.md, ops/HQ_CHECKPOINT.md (last note), ops/OWNER_REQUEST_LEDGER.md, plans/OWNER_METHOD.md.
