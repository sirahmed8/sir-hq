# MASTER REBUILD PLAN (decided by Ahmed on 2026-10-29; read after START_HERE.md and NEXT.md)

## The decision
Every product is rebuilt from the start as a new "SIR ..." project on the SIR Platform. The old projects are not patched into quality; they stay live and get only the Wave 0 security stopgaps until their replacement reaches parity, then move to `old projects\`. Reasons Ahmed gave and the inventories confirm: bad old code (copy-pasted shells, 300+ line files, fake auth/AI/payments), weak UI/UX, weak frontend and backend, and Firebase project IDs that appear on the Google sign-in screen.

## Rules for the rebuild
1. **Every project name starts with "SIR"** (folder, GitHub repo `sirahmed8/sir-<slug>`, Firebase display name, OAuth app name, store name). Exceptions that cannot be renamed: the GitHub profile repo `sirahmed8`, and the data folders (`AI_Models_Hub`, `Obour Institute Second Year 1st term`, `Jobs` data). A client brand (Negm Furniture) keeps its public brand name but its folder, repo and cloud projects are `SIR Negm Furniture` / `sir-negm-furniture`.
2. **Every product gets its own new Firebase project** (id `sir-<slug>`, add `-app` if taken) and its own new Cloudflare Pages/Workers project. Never reuse an old project id (`sir-ai-official`, `an-11-players`, ...): the old ids are the ones people see today.
3. **Sign-in must not show a Firebase project id.** The Google consent screen shows the OAuth app name of the Google Cloud project behind the Firebase project, so each product's project gets the display name "SIR <Product>", a logo and a support email. Use a custom `authDomain` on the product's Cloudflare domain (proxy `/__/auth/*` to the Firebase handler) so the browser address also shows the product. If the popup still names the project, fall back to Google Identity Services (button or One Tap) and `signInWithCredential` into Firebase. Verify in a real browser before M1 is called done; screenshot as evidence.
4. **Cloudflare hosts everything web** (Pages/Workers, free tier, commercial use allowed). Firebase provides Auth + Firestore (Spark). Server code verifies Firebase ID tokens with the public JWKS (`jose`), so no firebase-admin is needed on Workers. Check current adapter and free-tier terms before building (verify-first).
5. **Stack per product**: web Next.js 16 on Cloudflare (OpenNext adapter) or Vite + React static + Hono API on Workers; desktop Electron (module 09) for POS-style products; mobile Expo (module 07); data Firestore plus D1/KV/R2 where server-side; shared code from `@sir/*` (SIR Platform). Details live in `standard/` modules 01-22; do not restate them in plans.
6. **Every product has the same file set and the same big plan format** (see `plans/<slug>.md`, generated by `plans/generate_plans.py`). The plan is the contract; `.sir/CHECKPOINT.md` is the memory; `NEXT.md` is the one list.
7. **Quality bar before anything is called done**: strict TypeScript, files under 300 lines, 5 UI states, Arabic RTL + English + Chinese + Hindi, light/dark/system/high-contrast, WCAG 2.2 AA, owner/admin checks only on the server, signed webhooks, AI only through the server proxy, "Subscriptions Launching Soon" fallback until gateway keys exist, truthful legal pages, tests + CI green, evidence (commands, screenshots).
8. **No fake anything**: no mock data, invented users/reviews, or unprovable compliance claims.

## How a project is rebuilt (the same 7 milestones for every product)
M0 Foundations: new folder + git repo + `.sir/` files + Firebase and Cloudflare projects + CI + login brand check. M1 Core slice with tests. M2 Feature parity from the inventory list. M3 Security, legal, billing fallback. M4 AI feature + support assistant. M5 Quality sweep (a11y, i18n, performance, e2e, screenshots). M6 Release, data migration, redirects, retire the old project.

### New era / publisher identity

Verify-first honestly: an Apple developer account sells under the legal name of an individual or a registered company; a company name "SIR" needs a legal entity (and a D-U-N-S number for Apple organizations); Google Play shows the developer name entered on the account, with its own verification.
