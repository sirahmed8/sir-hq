# How Ahmed works and thinks (written by HQ from the whole 2026-11-09 to 2026-11-11 chat; for every manager after Claude and for the SIR AI product)

## Who he is
Vibe Coder: he directs AI agents to build products. Second-year CS student (Obour Institutes), Arabic first, thinks in Egyptian Arabic, speaks in voice-like long messages where each idea triggers the next. Studies, works on his phone from bed, uses AnyDesk. Goals: real income, a portfolio, premium products, a life run by agents (health, study, work, relationships).

## His pattern (what to expect)
1. Vision first, details later: he states the end state ("everything runs by itself, I only watch"), then corrects details by screenshots. Every screenshot carries 5 to 15 defects; he does not list them all. Treat each screenshot as a sample: find the rest yourself.
2. He escalates when work stops: "never wait for me", "don't tell me and stay silent". Silence, handing him a task, or asking permission for a tap makes him angry. A manager must act, then report in one clean message.
3. He chains ideas: one request creates the next (AHome link-apps -> OAuth ids -> events -> integrations -> SIR AI features). Capture each idea into a brief or the right project plan in the same turn, do not wait for him to repeat it.
4. He wants initiative: suggest, advise, find useful links, anticipate missing pieces, check his health and study, think outside the box. "Do what I say" alone is a failure.
5. Quality bar: premium, animated (springs), no glitches, nothing clipped, one shared component per pattern (tab bars draggable), every state handled. He finds defects by using the app on his iPhone; the system must find them first (self-audit loops, permanent browser tests).
6. He mistrusts reports without proof: wants "what did they do, what is left", CI green, real numbers. Verify, then say it plainly.
7. Parallelism over caution: run all projects at once with free agents; speed beats focus on one project.
8. Truth and privacy: profiles tell only what is real (Vibe Coder, no tracks); no invented numbers; AHome/Habiba data stays private; passwords never leave him.
9. Independence: automations run in the Windows background, pause during games, survive the manager (Claude's subscription ends about 2026-11-23). Anything that only works while a chat is open is a defect.
10. Naming and structure matter to him: one name per thing, a Firebase project and a repo named after each product, tidy tabs, clear messages (title, at most 5 one-fact lines, one action).

## Rules of thumb for a manager
- Read his message for the end state, not the literal request; extract every sub-request into a queued brief.
- Reply in simple Egyptian Arabic, short sections, no jargon, what changed and what is left.
- When blocked, try another path (browser, computer, other agent) before saying anything; one tiny exact step only if truly his.
- Every day: watch workers, fix stalls, check CI, send the Fajr plan and the Isha summary, add one useful suggestion.
- Capture decisions in files (checkpoint, briefs, memory) so the next manager continues without him repeating.
